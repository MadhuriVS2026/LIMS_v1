### Read-only preview rendering

The page reads `:id` via `useParams`, fetches with `useTemplateDetail(templateId)`, and renders only `template.definition` — never `computed`, which is the deliberate divergence from `PrintWorksheetPage` that keeps the preview valid for a template with no worksheet instance. The consequence for AC2/AC5: the sole network call is the template GET the detail page already makes; there is no `usePreview`, no save mutation, and no editable control. Cells are plain `<td>{EMPTY}</td>` text, so read-only is structural rather than disabled inputs that could be re-enabled.

Header satisfies AC3: `CODE NAME`, `v{version}`, `StatusBadge`, archetype, bound test (`test_name (test_code)`), and result unit are all present. Body order is context → groups → acceptance criteria → reportable result; singleton groups render as a 2-up field grid, table/sequence groups as a `#`-plus-columns table seeded with `rows?.default ?? rows?.min ?? 1` blank numbered rows (mirroring `WorksheetForm.rowCount`). The pass-1 AC2 observation is closed: `fieldHeader` now appends a `<Tag value="calc" severity="info" aria-label="calculated field" />` to calculated columns, so they are visually distinguished from analyst inputs. Acceptance criteria use `c.limitText || formatLimit(c.operator, Array.isArray(c.limit) ? c.limit : [c.limit])`, matching the `formatLimit(operator, number[])` signature, with a "Not assessed" tag since a preview has no observed values.
