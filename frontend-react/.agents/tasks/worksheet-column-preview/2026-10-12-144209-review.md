# Worksheet column + read-only worksheet preview for test templates

Adds a clickable "Worksheet" column to the Test Templates list that renders `CODE NAME` and navigates to a new read-only preview page. `WorksheetPreviewPage` is reached at `/test-templates/:id/worksheet`, reuses `useTemplateDetail`, and renders the worksheet layout skeleton from `template.definition` — context fields, group tables, acceptance criteria, reportable result — with em-dash placeholder cells, no inputs, no save, and no new backend calls. This is a later review pass: the working tree is now exactly four frontend files (three modified, one new), the backend `evaluator.py` edit and the unrelated chart feature flagged in pass 1/2 are gone, and calculated fields now carry a `calc` tag. The one remaining blocker is unchanged from the prior pass — there is no recorded build/lint evidence for this change.

**Watch for:** no `npm run build` / `npm run lint` output recorded anywhere for these four files — the feature is uncommitted and the task directory holds only `plan.md` and the prior reviews (confirmed).

### Route registration

```
/test-templates              → TemplateListPage
/test-templates/:id          → TemplateDetailPage   (unchanged)
/test-templates/:id/worksheet→ WorksheetPreviewPage (new)
```

The route is added after `/:id` inside `MainLayout`, so react-router matches the more specific `/:id/worksheet` ahead of `/:id` and the detail route is unaffected — the one place a route addition could regress the existing detail page.

### Read-only preview rendering

The page fetches via `useTemplateDetail(templateId)` and reads only `template.definition`, which is the one deliberate divergence from `PrintWorksheetPage` (that page reads `computed.rows` / `computed.values`, which only exist for a saved worksheet). The consequence for AC2/AC5: no `usePreview`, no save mutation, no editable control, and the only network call is the template GET the detail page already performs. Cells are plain `<td>{EMPTY}</td>` text, so read-only is structural rather than a disabled input that could be re-enabled.

Header satisfies AC3 — `CODE NAME`, `v{version}`, `StatusBadge`, archetype, bound test (`test_name (test_code)`), and result unit are all present. Body order is context → groups → acceptance criteria → reportable result, with singleton groups as a 2-up field grid and table/sequence groups as a `#`-plus-columns table seeded with `rows?.default ?? rows?.min ?? 1` blank numbered rows (mirroring `WorksheetForm.rowCount`).

Calculated fields are now distinguished from analyst inputs via a `calc` `Tag` in the column header:

```tsx
const fieldHeader = (field: FieldDef) => (
  <span className="inline-flex align-items-center gap-2">
    {header(field)}
    {field.kind === 'calculated' && (
      <Tag value="calc" severity="info" aria-label="calculated field" />
    )}
  </span>
);
```

This closes the pass-1 AC2 observation about undifferentiated columns. All imports (`useTemplateDetail`, `formatLimit`, `StatusBadge`, `FieldDef`/`GroupDef`) resolve against the current module shapes; `formatLimit(c.operator, Array.isArray(c.limit) ? c.limit : [c.limit])` matches the exported `(operator: string, limit: number[]) => string` signature, and `StatusBadge` accepts `template.status` since it takes `status: string`.
