## Findings that change the earlier design (verified against code and the live DB)

1. **The design's "no bare reference" claim is false for 7 templates.** `corel_weights.std1_weight` is a calculated field whose whole expression is the bare alias `standard.weight_mg` (A1-0001, A1-0002, A1-0003, A6A-0001, A6A-0002, A6A-0003, A6A-0004). Once `standard` is a table the alias evaluates to a `ColumnSeries` and is stored as a list (`[18.26]`, and `[18.26, 25.0, 25.0]` with three std rows) instead of `18.26`. `_as_number` never runs for a top-level alias, so the existing collapse does not cover it. Fix: collapse a `ColumnSeries` at the two scalar sinks the evaluator owns (calculated-field result and criterion `observed`). This reuses the same "first row at scalar coercion" rule, does not touch `_resolve`, and aggregates still see the full series. Safe for the catalogue: a scan of all 52 Active/Draft definitions found 0 top-level bare references to any current multi-row group (so nothing else changes), and `_prototype_equiv.py --sink` shows 0 diffs.
2. **The module is not authoritative for 9 of the 19 module-backed rows** (DB was edited after seeding). Comparing `SEED_TEMPLATES[code].definition` to the live Active/Draft row: identical for the in-scope A1-0001, A1-0003, A2-0006, A4-0001, A6A-0005, A6B-0001, A6B-0002, A8-0004, NITRO-0001. Drifted (in scope): A2-0001 and A13-0001 and A6C-0001 (context only), A2-0003 (std_injections, bkt_injections), A3-0001 (24 groups), A4-0004 (unknowns), A12-0001 (stats, bkt, preps), A6A-0001 (18 groups including the `standard` group itself: DB has `Wt. in mg` labels and `rounding` on `conc_ppm`), A8-0001 v2 (9 groups including `standard`, DB name differs, `std_prep_procedure` exists only in DB). Copying a module over these rows would change calculations (e.g. the rounding on A6A-0001 `conc_ppm`). **Decision: the live sync never copies a whole module. It applies a surgical, shared transform to the live definition** (`convert_definition`) and checks the result. Drift is reported in the roster, not fixed.
3. **Seven in-scope rows have no module:** A1-0002, A6A-0002, A6A-0003, A6A-0004, H1-0001, H1-0002 (Active) and A8-0003 (Draft). They are handled only by the same surgical transform, declared in source in a `ROSTER` constant and covered by the before/after harness. They are not captured into new modules (that would import hand-edited DB JSON into source, which is out of scope and unverifiable).
4. **Four existing assertions read the flat mirror `result.values["standard.conc_ppm"]`**, which the evaluator only emits for non-multi-row groups: `tests/calculation/test_seeded_template_parity.py` lines 141 (TestA1Assay), 360 (TestA3SaturationSolubility), 631 (TestA6BDissolutionWithReplacement); `tests/calculation/test_a6b_0002_octreotide_parity.py` line 72. They must read `result.rows["standard"][0]["conc_ppm"]` (same expected numbers; the A6A-0005 and NITRO parity tests already do). `test_assay_template_e2e.py` and `test_dissolution_a6a_release.py` build their own inline singleton definitions and are untouched.
5. Nothing in `backend-v2/src` special-cases `standard` (grep of `'standard'`/`"standard"` finds none). The frontend reads `computed.values[...]` only for definition-supplied refs (footers, charts, showIf). No definition contains such a ref to `standard`/`standard_2` (the scan walks every string in every group and in `criteria`, `resultRef`, `context`).
6. ## Helper strategy (`scripts/template_definitions/_common.py`)

The user overruled the "keep `standard_2` singleton" rule, and every caller of `standard_group()` is now in scope (callers: a1_assay, a2_a3_content x2, a4_a5_related_substances x2 (`standard`, `standard_2`), a4_rs_against_standard_rrf_division, a6_dissolution `_standard_groups`, a8_content_uniformity, a8_cu_tablets_30units, a9_a10_a13_classical, a12_derived_rollups; A11 and lenacapavir do not call it). So the opt-in flag from the earlier design is dropped: **`standard_group()` always emits the table shape.** That makes a forgotten call site impossible and keeps one source for the shape. Add to `_common.py`:

- `STANDARD_ROWS = {"min": 1, "max": 10, "default": 1}`, `STANDARD_ROW_LABEL = {"format": "STD - {n}"}` (copied with `dict(...)` at each use so no two groups share a dict).
- `standard_group(...)`: return `{"key": key, "kind": "table", "label": label, "rows": dict(STANDARD_ROWS), "rowLabel": dict(STANDARD_ROW_LABEL), "fields": fields}`. Signature otherwise unchanged.
- `as_standard_table(group: dict) -> dict`: deep copy; if `kind == "singleton"` set `kind="table"`, `rows`, `rowLabel`, pop `renderAsTable`; if already `table`, return unchanged copy (idempotent); never mutate the input. This is the single transform used by the inline module sites that are easier to wrap, and by the live DB sync.
- Seven inline literals (not helper-built) are edited in place: `kind` -> `table` plus `"rows": dict(STANDARD_ROWS), "rowLabel": dict(STANDARD_ROW_LABEL)`. `a2_lyso_content.py` (already done) keeps its literals; a test asserts it equals the constants.
- `a4_rs_against_standard_rrf_division.py`: replace `{**standard_group(...), "renderAsTable": True}` by `standard_group(...)` and rewrite the comment above it (it currently says `kind:"table"` would break scalar references; the engine rule now makes that safe).

## Before/after evaluation approach (the proof for the HARD constraint)

Two layers use the same harness code (`scripts/standard_tabular_rollout.py`):
- **Module layer (pytest, no DB):** for every template in `SEED_TEMPLATES` that has a converted group, `legacy = revert(new)` (test-side inverse: `kind=singleton`, drop `rows`/`rowLabel`) and compare `legacy` vs `new`.
- **Live layer (sync tool, reads DB):** for each of the 25 rows, `old = stored definition`, `new = convert_definition(old, ROSTER keys)`; compare `old` vs `new`.

Per template, evaluate both with these inputs and compare: (1) `{}`; (2) a deterministic synthetic fully-filled sheet (counter-based numbers, text/date/select by field type, context defaults honoured; port from `_prototype_equiv.py`); (3) in the live layer, every stored worksheet whose `template_id` is that row (63 total, 25 of them on target rows); (4) padded variant: converted groups carry 3 rows with distinct inputs. For (4), every cell outside the converted groups must equal the 1-row baseline of the old definition (row 1 stays authoritative), and each extra row's calculated fields must equal what the old definition computes when given that row's inputs as its single row.

Comparison rules: cells are `rows[group][i][field]` for all groups, `values[key]` for context and singleton mirrors except the flat `"standard.*"`/`"standard_2.*"` keys of converted groups (their logical cell is `rows[group][0][field]`), each criterion `(key, observed, passed, limit, severity)`, and `reportable_result`. Exact `==` (EMPTY equals EMPTY). A list or `ColumnSeries` value in the new result where the old was scalar fails. Coverage gate: the synthetic run must produce at least one non-blank calculated cell per template; the tool prints non-blank counts and reportable value so a blank==blank pass is visible.

Static reference audit (hard gate before any write, also a pytest): across the converted definitions, every reference to a converted group from outside it must be one of: operand of a binary/unary operator, first/second arg of `round/trunc/abs/sqrt/ln/log10/exp`, explicitly indexed, or the whole expression of a calculated field (allow-listed only for `corel_weights.std1_weight` = `standard.weight_mg`, which the sink collapse covers). Anything else (argument of `if/coalesce/number/min/max/sum/count/mean/...`, `and/or/not`, whole-group reference, criterion target, `resultRef`, footer/chart/showIf ref) fails the template. Current result: 0 violations for the 25 rows (A11 is excluded because its `standard` is already a table).

Aggregate coverage requirement ("aggregates over multi-row standard groups use all rows"): pytest probe. For each converted module template and each converted group, append a singleton group `probe` with calculated fields `mean(<g>.<f>)`, `sd(...)`, `count(...)` on the first numeric input field, evaluate with 3 distinct rows, and assert mean == arithmetic mean of all three, count == 3, sd == `statistics.stdev`. Plus the engine tests in `tests/calculation/test_evaluator.py::TestMultiRowScalarCollapse` already pin `mean`/`sd`.
